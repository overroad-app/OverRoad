# 급제동 경고 지연시간 실측

측정일 2026-11-04 · 10/10회 성공 · `scripts/scenarios/measure_latency.py`

환경: Pleos Connect 에뮬레이터 2대(B 급제동 차량, C 90m 뒤 차량) + 같은 PC의 중계 서버.
실제 차량은 이동통신망을 거치므로 전달 구간에 수십~수백 ms가 더해질 수 있다.

| 구간 (ms) | 평균 | 중앙값 | 최소 | 최대 |
|---|---|---|---|---|
| ① 감지: 브레이크 명령 → B 앱 급제동 판정 | 631 | 664 | 519 | 755 |
| ② 전달: B 판정 → 서버 → C 화면 경고 | 6 | 6 | 4 | 7 |
| 전체: 브레이크 명령 → C 화면 경고 | 637 | 670 | 525 | 761 |

- ①은 감속이 기준(감속도·브레이크 입력)을 넘을 때까지 기다리는 시간이 대부분이다.
- ②는 같은 PC 안에서 오가므로 매우 짧다. 보정 오차보다 작은 값은 "수 ms 수준"으로만 해석한다.
- 기기 시계는 adb로 호스트 시계와의 차이를 재 보정했다 (보정 오차 최대 약 18ms).
- 비교: 기존 내비 교통정보는 여러 차량의 위치를 모아 주기적으로 갱신하므로, 갑자기 생긴 상황이 반영되기까지 공백이 있다. OverRoad는 에뮬레이터 실측으로 돌발 상황을 1초 안에 뒤차 화면까지 전했다(같은 PC 기준이며, 실제 이동통신망에서는 아직 재지 못했다).
